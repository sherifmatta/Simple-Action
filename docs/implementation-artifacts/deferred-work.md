- source_spec: `docs/implementation-artifacts/spec-1-6-issue-and-resolve-the-client-identity.md`
  summary: Replace the hand-written `mintIdentityId` with the pinned `uuidv7` package once it is installed.
  evidence: AR-19 and `ARCHITECTURE-SPINE.md:204` pin `uuidv7 1.2.x`, but the package is not in `package.json` and Story 1.6 was not permitted to add a dependency. `src/server/identity/identity-token.ts` therefore carries a ten-line RFC 9562 v7 generator over `crypto.getRandomValues`. Epic 3 needs the package client-side anyway (AD-4 mints Todo ids in the browser), and the architecture's `.memlog.md` notes its `V7Generator` handles monotonicity and clock rollback — which the local version deliberately does not, because `client_identity.id` is never a sort key and `todo.id` is. When the package lands, `mintIdentityId` should become a one-line re-export and the local implementation should go, or the two generators drift.

- source_spec: `docs/implementation-artifacts/spec-1-6-issue-and-resolve-the-client-identity.md`

  evidence: `SOURCE_EXTENSIONS`, `SKIPPED_DIRECTORIES` and `sourceFiles()` are duplicated in `src/server/repository/client-identity.test.ts`, `src/shared/contract/contract.test.ts` and now `middleware.test.ts`. - source_spec: `docs/implementation-artifacts/spec-1-6-issue-and-resolve-the-client-identity.md`
  summary: Every API request will resolve the Client Identity twice — once in middleware, once in the route handler — unless the resolved `ownerId` is forwarded upstream.
  evidence: `middleware.ts` resolves on every matched request to enforce AC4's `401`, and the route handlers of Epics 2-5 must resolve again to get the `ownerId` their repository calls are scoped by. That is two identical indexed `SELECT`s per API call. Next.js's own guidance (`node_modules/next/dist/docs/01-app/01-getting-started/16-proxy.md`) says Proxy "is not intended for slow data fetching"; the documented remedy is `NextResponse.next({ request: { headers } })` to pass the resolved value upstream, which is safe here only because middleware covers every `/api/**` path and therefore always overwrites a client-supplied header. Deferred because it establishes a trusted-header contract that the first route-handler story (2.1) should choose and test, not one this story invents for a caller that does not exist.

- source_spec: `docs/implementation-artifacts/spec-1-6-issue-and-resolve-the-client-identity.md`
  summary: Any extensionless request that is not a real route still mints a Client Identity and writes a row — including 404s and case variants such as `/API/todos`.
  evidence: The document matcher covers every path that is not `/api`, not `/_next` and carries no dot, so `/random-404-path` mints, and a crawler that stores no cookie creates one row per request with no cap and no cleanup (Story 1.4 fixed the repository at a lookup and a create, so there is no delete). `ARCHITECTURE-SPINE.md`'s Deferred section already accepts unbounded identity rows — "the exposure is storage cost on a free tier" — which is why this was not patched. The narrowing fix is to list the real document routes in the matcher, which trades the storage cost for a footgun: a future page whose route is not added to the matcher gets no identity and silently `401`s. That trade belongs with whoever adds the second page route, or with the rate-limiting revisit the spine already flags.

- source_spec: `docs/implementation-artifacts/spec-1-6-issue-and-resolve-the-client-identity.md`
  summary: Two cookie-less document requests in flight together still mint two identities; AD-17 narrows the race rather than closing it.
  evidence: AD-17 moves issuance to the document request so a first visit's `GET` and `POST` cannot each mint. Two document requests from the same fresh browser at once — two tabs restored on launch, a prefetch alongside a navigation — both resolve to `undefined`, both mint, and both insert. The browser keeps whichever `Set-Cookie` arrives last and the other row is orphaned, carrying no Todos. Harmless today because no Todo can exist before the cookie settles, and closing it needs a dedupe or a lock that costs more than the orphan row. Worth revisiting alongside the row-growth entry above.

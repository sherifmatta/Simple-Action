### Scope — did "measure only" hold?

The epic's hard rule (`epic-6-context.md:7`): "Epic 6 may contain only what measures a
finished artifact", with two allowed exceptions — the live-measured sticky-block offset, and
fixes surfaced by an audit. Narrowed at `:50` to "Story 6.2 is the only story permitted to
add code."

**That narrower claim holds under measurement.** Every non-test product change is in
`09b1c13`. Five of the eight files are the sticky-offset exception and are clean against the
spec's own execution list: `sticky-block-offset.ts` (+117, new), `sticky-block-contract.ts`
(+38, new — unplanned, but disclosed in `spec-6-2:348-356` because a Server Component cannot
import a module carrying `useLayoutEffect`), `sticky-top-block.tsx` (+21/-4, one attribute),
`todo-row.tsx` (+2/-2, one class token on each of two controls), `app/globals.css` (+44, two
declarations and 42 lines of comment, no `@theme` entry).

**Finding S1 — `medium` — "surfaced by an audit" was read as "routed to an audit".**
`add-input.tsx` (+80), `error-banner.tsx` (+48/-1) and the decision-2 half of `todo-list.tsx`
close defects logged in Epics 2 and 3 — `deferred-work.md:232` (Retry drops focus to body,
raised by Story 2.6), `:236` (empty list announced twice), `:284` (counter silent to screen
readers, `source_spec: spec-3-2`). None was surfaced *by* an Epic 6 measurement.

guess", and `spec-6-2`'s frozen block (`:108-134`) read that as authorising three fixes and

approved block, not a leak — but it is the widest available reading of the epic's second
exception, and `add-input.tsx` at +80 lines is the largest piece of construction in an epic

lesson is the wording: "surfaced by" and "routed to" are different sets, and the spec should
say which it means.

**Finding S2 — `low` — behaviour was added that no criterion asked for.**

### The Gate

`epic-6-context.md:25`: "**100% of tests pass before the epic is accepted.** One inherited
caveat must be closed rather than allowed to close silently — the live-database repository
tests have been failing on stale credentials and so were asserted rather than demonstrated;
they must run green against a working database connection string."

- **Vitest: met.** 58 files / **1,325 tests / 0 failed / 0 skipped**, exit 0, observed at
  `d20bff4`.
- **The inherited caveat: closed, and verified rather than taken on trust.**
  `npx vitest run src/server/repository/` → **42 passed against the live Neon branch**. With
  `DATABASE_URL` blank the run fails at module load (`src/server/repository/client.ts:28-33`
  throws), so the "asserted rather than demonstrated" failure mode is structurally
  unavailable — the tests cannot silently skip. This was Epic 6's one explicitly inherited
  debt and it is genuinely discharged.
- **Playwright: met, with a caveat worth recording.** Observed **five green runs**
  (93 passed / 13 skipped / 0 failed, ~18 s each). One **red** run was also observed —
  7 failures, all `touch`, 8.7 min wall — but it ran while a production build, a running
  server and an 8-minute `madge` scan were competing for the same machine, and all 7 passed
  in isolation in 7.6 s. A 29× wall-clock slowdown with seven 60 s timeouts is resource
  starvation, and the starvation was created by this retrospective's own parallelism. It is
  **not** evidence against the product. It *is* evidence that the suite's 15 s assertion and
  60 s test timeouts have little headroom, which matters because CI runs on a 2-core
  `ubuntu-latest`. **Finding G1 — `low` — recorded as a CI-headroom risk.** `retries: 2` in CI
  covers it today.

**Finding G2 — `medium` — one half of the gate has never been exercised.**
`epic-6-context.md:35` makes it a technical decision that "the suite must pass in CI against
the same commit that deploys." `.github/workflows/ci.yml` exists and its exact sequence passes

### Process lessons

- **"Surfaced by an audit" and "routed to an audit" are different sets.** The epic's second
  exception was written as the former and used as the latter, which is how +80 lines of
  construction entered an epic whose premise is that it builds nothing. Future scoping rules
  should say which they mean.
- **A planning premise that justifies a technical decision should be marked as an assumption
  to verify.** `epic-6-context.md`'s banner-occupancy claim was stated as fact, was wrong, and
  was only caught because this epic measured it.
- **A new top-level directory does not inherit the project's lint blocks.** The story that
  creates one should update `eslint.config.mjs` in the same commit, or the guarantee silently
  stops at the new boundary.
- **A convention written down mid-epic does not retro-apply.** Story 6.3 wrote the
  verbatim-quoting rule for ledger closures; Story 6.2's five closures predate it and do not
  comply. Conventions discovered during an epic need a sweep of what came before them.
- **The workflow's defer-agent-context rule can hold a known-false instruction in place.**
  Story 6.3 existed partly to fix `AGENTS.md`, wrote a wrong sentence into it, and the review
  that caught the error was barred from correcting it by the same rule that had already
  bounced the work forward from Epic 1 twice.

## Acceptance verdict

**accepted-with-open-items.** Criteria were **declared** (`epic-6-context.md`
§Requirements & Constraints), not profiled.

**Why accepted.** All three stories are `done`; `pending_stories` is empty, so no forced
rejection applies. The gate's measurable half is met and was verified here rather than read:
Vitest 1,325/1,325 with zero skipped, and five green Playwright runs. The one inherited debt
the epic was required to close rather than let close silently — live-database repository tests
running green against a real connection string — is genuinely discharged, and the failure mode
it guarded against is now structurally impossible rather than merely absent. All four success
metrics have executable evidence, every forced-failure path asserts exact copy and revert
behaviour, and the audit constraints are the best-evidenced work in the epic (contrast
recomputed from the design table with negative fixtures; clearance proved with a fixture that
confirms the check can fail). The product was exercised end to end here and behaves as claimed.

**Why with open items, not clean.** Four things are genuinely outstanding, each named and
tracked rather than discovered: the CI half of the epic's own gate has never run (G2);
`AGENTS.md` ships an instruction that is false and will mislead the agents it was written for
(R6); AC2's per-step comparison is missing a row (Documentation); and the headline metric's
discoverability tripwire cannot trip (R4). None is a defect in the shipped product, and none
was concealed — every one of them is recorded in the specs or the ledger with what would close
it, which is the behaviour the epic asked of itself.

**Machine verdict, no human override sought** (headless run).

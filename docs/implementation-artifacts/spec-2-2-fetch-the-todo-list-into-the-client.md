## Intent

**Problem:** `GET /api/todos` exists (2.1) and `TODOS_QUERY_KEY` exists (1.7), but nothing connects them: `src/client/todos/` holds only `query-keys.ts`, so no component can read a Todo and the skeleton, empty and error states of 2.6–2.8 have no loading, success or failure state to render against. Nothing in the application calls `fetch` yet either, which means AD-8's "exactly one query key" is still enforced only by the source scans Story 1.7 shipped — `deferred-work.md` records the lint rule as this hook's to own, because this is the first call site the rule could be written against.

**Approach:** Add the one query hook, `useTodos`, as `useQuery` over the existing `TODOS_QUERY_KEY` — an inline loading state, not a Suspense boundary, because EXPERIENCE.md keeps the card, input and tabs real and interactive while only the list region is skeletal. Split it the way `error-slot-state.ts` / `error-slot.tsx` already are: the request and its `queryOptions` live in a React-free module so the cache contents, the `id DESC` order as received, and the error classification can all be proved under Vitest's existing `environment: "node"` — this story adds no DOM, leaving jsdom and the `.tsx` glob to the epic's first component test. Every failure the hook reports — a non-2xx response, a body that is not an array, or a transport failure where no response arrived — is classified as error kind `load`, by the operation attempted rather than by what came back (AD-10). Then close the carried-over item: a `no-restricted-syntax` rule making a `queryKey` that is not `TODOS_QUERY_KEY` a lint error, with fixtures in `eslint.config.test.ts`'s existing harness.

## Implementation Notes

**Files.** New: `src/client/todos/todo-list-query.ts` (`TODOS_ENDPOINT`, `TodoRequestError`, `fetchTodoList`, `todoListQueryOptions`) and `src/client/todos/use-todos.ts` (`useTodos`), each with a node test beside it. Amended: `eslint.config.mjs` (the AD-8 rule, restated in all ten blocks) and `eslint.config.test.ts` (eight violation fixtures, three exemptions, and `"AD-8"` added to the `names` union). No new dependency, no schema change, no DOM environment, no change to `vitest.config.mts`.

**The split is for testability, and it bought the whole AC set.** `todo-list-query.ts` holds the request and the `queryOptions`; `use-todos.ts` is three lines of React over them. That mirrors `error-slot-state.ts` / `error-slot.tsx` and means a real `QueryClient` can `fetchQuery` the same options `useQuery` receives — so AC4's cache order and AC5's classification are proved against the library's own behaviour under `environment: "node"`, with no jsdom and no `@testing-library/react`. `use-todos.test.ts` checks only the wiring, from the AST: one `useQuery` call taking the identifier `todoListQueryOptions` and nothing inline.

**Classification lives in one place, and that is what makes AC5 structural.** `readTodoList` throws plain `Error`s and decides no kind; `fetchTodoList` wraps every one of them — and any transport rejection — in `TodoRequestError("load")`. Nothing on the path can read a kind off a response body, so "classified by the operation attempted, not by the response" (AD-10) is true by construction rather than by discipline. A `500` carrying `{ kind: "create" }` still reports `load`; a test pins that. `TodoRequestError` carries the shared contract's `ErrorKind`, so Epics 3–5 throw the same class and Story 2.7's banner reads `.kind` with no translation table.

**Two non-default query options, both forced by the designed states.** `retry: false` — TanStack's default of three retries with backoff would hold the skeletons pulsing for roughly seven seconds before the load-failure banner appeared, and would leave a `Retry` press racing a retry already in flight; AD-9 makes recovery an explicit user action. `networkMode: "always"` — under the default `"online"`, a fetch attempted while the browser reports itself offline is *paused*, not run: the query stays `pending`, never errors, and the list region pulses with no banner and nothing to press, which is exactly the stuck interface NFR-4 forbids. This one was found by reading `@tanstack/query-core`'s `retryer.ts`, not from the ACs. Reading the same file also removed a branch: `cancel()` rejects the retryer's own promise and marks it resolved *before* aborting the signal, so a rejection arriving from our `queryFn` afterwards is dropped — a cancelled read cannot raise a banner, and the abort branch I first wrote for it would have been untestable through the query.

**`staleTime` and `refetchOnWindowFocus` stay at their defaults** (`0` and `true`), which Story 1.7 left for this epic to settle. Every consumer of the list — the list region, the empty state, Epic 4's tab counts — mounts in the same commit inside one card, so `staleTime: 0` costs one request rather than one per consumer; and a refetch when the window regains focus is this product's whole answer to a second tab having changed the list. Recorded here because it is a choice, not an omission.

**The body is trusted element-wise and checked shape-wise.** AD-3 makes the wire `Todo` a type-level contract and one deployable serves both sides, so per-field validation would re-derive what the deployment already gives. That a JSON array arrived at all is a different claim: a proxy or a captive portal answers `200` with HTML, and without the `Array.isArray` guard that lands in the cache as the Todo List and fails in a renderer instead of in the designed load-failure state.

**AD-8's lint rule closes the carried-over item** recorded against `spec-1-7`. `no-restricted-syntax` now rejects an `ObjectExpression` property named `queryKey` whose value is not the `TODOS_QUERY_KEY` identifier — including the string-key and shorthand spellings. Scoping it to `ObjectExpression >` is what measures the false-positive surface the deferred entry said could not be measured yet: `queryFn: ({ signal }) => …` and `queryFn: ({ queryKey }) => …` are `ObjectPattern` properties, TanStack handing the key back, and three exemption fixtures pin that they stay allowed. Per the file's FULL RESTATEMENT invariant the rule is restated in all ten config blocks, with fixtures for the three — route handler, repository, repository root — that no `src/client/**` fixture would reach. The `deferred-work.md` entry is left as written; entries there are an append-only record.

**AC3 has no lint rule, so it is a tree scan.** `use-todos.test.ts` parses every non-test `.ts`/`.tsx` file and flags a `useState`/`useReducer` whose type arguments name `Todo` or whose value arguments name a Todo. The type half is strong — `Todo` is the only definition of a Todo and a typed holder cannot avoid it. The name half is a proxy, and it deliberately errs towards catching too much: `todoDraft` tripping it in a later story costs a rename, while a Todo list living quietly in React state costs an optimistic rollback that is right in the cache and wrong on screen. A vacuity case plants five holders and three pieces of legitimate client state (Filter View, dialog flag, draft text) to prove the detector separates them. AC2 needs nothing new: `eslint.config.test.ts` already pins the fetch wall from Story 1.1, and `src/client/todos/` is its sanctioned exemption.

**Verified:** `npm run lint`, `npm run typecheck`, `npm test` — 353 tests across 20 files, all passing.

### Review Findings

Code review 2026-09-22 (blind-hunter, edge-case-hunter, verification-gap, acceptance-auditor over `cabcab9..HEAD`).

- [x] [Review][Patch] No request deadline anywhere on the read [src/client/todos/todo-list-query.ts:64-67] — **resolved 2026-09-22: a 15s deadline, `AbortSignal.any([signal, AbortSignal.timeout(15_000)])`.** The file argues that pausing a query offline "is precisely the stuck interface NFR-4 forbids", but `fetch` had no timeout and `retry: false` means nothing ever gives up, so a half-open connection leaves the query `pending` indefinitely — the same forbidden state by a different route. The deadline makes it surface the designed load-failure banner instead.

- [x] [Review][Patch] The abort signal is asserted on `fetchTodoList` but never through the options that carry it [src/client/todos/todo-list-query.ts:149] — pre-verified: changing the `queryFn` to `() => fetchTodoList()` drops cancellation for every consumer and ships 22 files / 406 tests green. The test named "forwards the abort signal it is given" calls the function directly and bypasses the options object.

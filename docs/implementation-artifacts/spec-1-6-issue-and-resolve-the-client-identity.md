## Intent

**Problem:** `src/server/identity/` holds only a `.gitkeep` and `middleware.ts` is a pass-through whose own comment says Story 1.6 fills it. The schema (1.3) and the repository's two identity functions (1.4) exist, but nothing mints a token, nothing hashes one, and nothing resolves a cookie into an owner. Until that lands, every browser is anonymous to the server: FR-6 (a Todo List that is still there tomorrow) has no mechanism, and the route handlers of Epics 2–5 have no `ownerId` to scope a query by. AD-17 also puts the issuance on the *document* request specifically — build it per-endpoint later and a first visit's in-flight `GET` and `POST` each mint an identity, splitting the user's first Todo away from the list being read.

**Approach:** Give `src/server/identity/` the token mint, the SHA-256 hash, the cookie's name and attributes, and a resolve-from-cookie that only ever *looks up*. Then make `middleware.ts` the one place that issues: on a document request it resolves the cookie or mints a token, creates the `client_identity` row, and sets the cookie with `HttpOnly`, `Secure`, `SameSite=Lax` and an explicit long `Max-Age`. Extend the same middleware over `/api/**` so a request there is resolved and never minted, and one without a valid identity is answered `401` with the shared error envelope — which makes AC4 true for every route handler by construction rather than by per-route discipline, before any route handler exists. Persist the AC5 and AC6 guarantees as source scans in the style Stories 1.4 and 1.5 established.

</frozen-after-approval>

## Implementation Notes

**Files.** `src/server/identity/` gained `identity-token.ts` (mint, hash, UUIDv7 id), `identity-cookie.ts` (name and attributes) and `request-identity.ts` (resolve from a request, and the `401`), each with a colocated test; its `.gitkeep` is gone, per Stories 1.3–1.5's precedent. `middleware.ts` went from a pass-through to the issuer, and `middleware.test.ts` from a matcher-only suite to the AC1–AC7 suite. Nothing else was touched: no schema, no migration, no repository change, no lint rule, no dependency.

**The 401 lives in `middleware.ts`, not in each route handler.** AC4 binds "any route under `app/api/`", and no route handler exists yet — so a per-route check would have been an unenforceable rule written into a spec rather than a behaviour. Extending the matcher over `/api/**` and refusing there makes AC4 true for every route handler by construction, before the first one is written, and is the pattern Next.js's own Proxy reference documents (`return Response.json(..., { status: 401 })` from the proxy). Route handlers still call `resolveClientIdentity` for the `ownerId` they scope on; this is the wall in front of them, not a substitute for the ownership check AD-2 puts in the repository.

**The matcher is two entries, and the second one is load-bearing.** The document entry keeps Story 1.1's shape, including its `.*\..*` exclusion for robots.txt, favicon.ico and `/_next/data/*.json`. That exclusion would also exempt a route handler whose path carried a dot, which AC4 cannot allow, so `"/api/:path*"` is listed separately with no extension carve-out. `/api` itself carries no extension and is already covered by the first entry. Verified through `unstable_doesMiddlewareMatch`, which runs the same `getMiddlewareMatchers` conversion `next build` does — `/api/todos.json` matches, `/api-docs` and `/_nextdoor` are documents, `/robots.txt` and the build assets are neither.

**`unstable_doesMiddlewareMatch` is imported from its own module, not the public barrel.** `next/experimental/testing/server` re-exports the app-render helpers too, and importing it under Vitest's `node` environment throws `Invariant: AsyncLocalStorage accessed in runtime where it is not available` before any test runs. `next/dist/experimental/testing/server/middleware-testing-utils` loads cleanly. The Next.js 16.3.5 export is named `unstable_doesMiddlewareMatch`; the documentation for this version already calls it `unstable_doesProxyMatch`.

**Web Crypto, not `node:crypto`.** Proxy defaults to the Node.js runtime in Next.js 16, so `node:crypto` would work today — but `crypto.getRandomValues` and `crypto.subtle` are standard in Node 24 and are also the only spelling that survives this ever running on the Edge runtime. The cost is that `hashIdentityToken` is async, which costs nothing on paths that were already async.

**The token and the hash are both 64 lowercase hex characters, and are never equal.** 256 bits is AD-7's figure; hex rather than base64url so the cookie value needs no encoding rules of its own — every character is already a valid `cookie-octet`. The digest is taken over the token's UTF-8 bytes, not over the bytes its hex spells.

**`Max-Age` is 400 days, and Next.js adds `Expires` on top.** AC2 needs an explicit long `Max-Age` because a cookie with neither `Max-Age` nor `Expires` is a session cookie and dies with the browser. 400 days is the longest value worth writing: Chromium clamps anything larger. Next.js's cookie serializer then derives an `Expires` from `maxAge`, so the response carries both and they agree — the first draft of the test asserted `Expires` was absent and failed, which is how this was found.

**`secure: true` is unconditional.** Browsers treat `http://localhost` as a trustworthy origin and store `Secure` cookies there, so no environment-dependent relaxation is needed — and a flag that is off in development is a flag nobody tests.

**An unknown cookie mints; a valid one does not.** AC3 is scoped to a *valid* cookie. A token naming no row — forged, or a row since removed — falls through to the minting path, because the alternative is a browser permanently locked out of the product by a cookie it cannot clear.

**UUIDv7 is generated in-repo rather than by the pinned `uuidv7` package.** The stack pins `uuidv7 1.2.x` but it is not installed, and this build was not permitted to add a dependency. `mintIdentityId` is a ten-line RFC 9562 layout over `crypto.getRandomValues`: 48-bit big-endian Unix milliseconds, version 7, the `10` variant, the rest random. Monotonicity within a millisecond is deliberately absent — it matters for `todo.id`, which AD-5 makes the sort key, and `client_identity.id` is never sorted on. **When `uuidv7@1.2.x` is installed (Epic 3 needs it client-side for AD-4), `mintIdentityId` should become a one-line re-export of `uuidv7()` and this implementation should go.** Recorded as a deferred item.

**`middleware.ts` keeps its name although Next.js 16 deprecates it.** `next build` prints the `middleware` → `proxy` notice on every run (it did before this story too). The rename is not done here because AC6 and ARCHITECTURE-SPINE's source tree both name `middleware.ts` by hand; it is a repository-wide rename with its own codemod, not a side effect of this story.

**The repository is mocked in both new suites, departing from Story 1.4's live-test pattern.** Two reasons. First, what is under test is which repository call middleware makes and with what — a spy states "no identity is created" (AC3, AC4) far more directly than a row count, and Story 1.4's live tests already prove those two functions really read and write Neon. Second, Story 1.4 fixed the repository's exported surface at a lookup and a create, and asserts it; there is no delete, so a live test outside `src/server/repository/` has no way to remove the rows it inserts and would leave them on the branch. The whole suite still runs offline for these files.

**AC6 is a source scan, and it is the third copy of the tree walk.** It finds every non-test file naming `mintIdentityToken`, `mintIdentityId` or `createClientIdentity`, excludes each symbol's defining module, and asserts the result is exactly `["middleware.ts"]`. Anti-vacuity cases assert the scan still finds each defining module and finds nothing for a symbol that does not exist. `SOURCE_EXTENSIONS`/`SKIPPED_DIRECTORIES`/`sourceFiles` are copied from `client-identity.test.ts` for the third time — Story 1.5's notes said a third scan was the moment to place a shared helper deliberately, but every candidate home widens a module whose contents an earlier story's tests assert exactly (`src/shared/contract/` is fixed at three files, `src/server/repository/` at two), so the extraction is left as deferred work rather than done as a side effect here. One comment in `request-identity.ts` was reworded so it does not name the repository's create — the scan is textual, and prose naming the symbol would read as a second minting site.

**An unreachable identity store degrades rather than breaks (added after review).** Neon auto-suspends and Story 1.4 measured several seconds to wake, so a rejected query in middleware is an ordinary transient. Letting it propagate replaced the whole document with Next.js's error page — a database blip looking like a broken product — and produced an unenveloped 500 under `app/api/`, which AD-10 forbids and the single error slot cannot classify. The document request is now served without a cookie: the shell renders, its API calls answer `401`, the user sees the designed load failure with its Retry (AD-9), and the next document request mints. An API request answers `503` rather than `401`, because `401` asserts the caller has no identity and the truth is that we cannot tell. The failure's `message` is logged and never the error object, which carries the query, and never the token.

**AD-17's double-mint window is narrowed, not closed.** Two document requests from the same cookie-less browser in flight together — two tabs restored on launch, a prefetch beside a navigation — each resolve to `undefined` and each mint. The browser keeps the last `Set-Cookie` and the other row is orphaned, carrying no Todos. AD-17's concern was the first-visit `GET`/`POST` race, which this closes completely; the residual is recorded in `deferred-work.md` rather than solved with a lock.

**The 401's error kind comes from the request method.** AD-10 classifies a failure by the operation attempted, and under `app/api/` the method is the operation: `POST` → `create`, `PUT`/`PATCH` → `update`, `DELETE` → `delete`, everything else → `load`. `GET` is the default rather than a case of its own, so an unplanned verb still produces a kind the single error slot can classify. The envelope type is imported from `@/shared/contract/errors`, never redeclared — Story 1.5's repo-wide duplication scan enforces that.

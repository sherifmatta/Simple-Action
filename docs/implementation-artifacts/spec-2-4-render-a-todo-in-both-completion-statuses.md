## Intent

**Problem:** Nothing in this product has ever rendered a Todo. Story 2.1 serves the list, Story 2.2 fetches it into `useTodos()`, and Story 2.3 built the card with an empty list region waiting for it — but `useTodos` has no caller, so the screen is still blank and the hook's success branch is unexercised. The row is also the geometry every later state is measured against: Story 2.6's skeletons must match an Active row's fill, radius, padding, shadow and 44px minimum height exactly or the swap shifts layout, and it cannot match what does not exist. Two obligations already name this story as their owner — `deferred-work.md` records that no wrapping guard exists anywhere in the product for the 500-character unbroken Todo the epic names, because until now no element rendered Todo text to put one on.

**Approach:** Build `TodoRow` — checkbox glyph plus text, in DESIGN.md's `todo-row-active` and `todo-row-completed` recipes — and the `TodoList` that reads `useTodos()` and renders rows into the list region Story 2.3 left for it. Completion Status is expressed exactly once, as a single variant marker on the row that every descendant derives from through a Tailwind variant (AR-28), which also keeps every `className` a static string literal and so keeps the whole-tree scans Story 2.3 built from going blind. The three values DESIGN.md gives with no token behind them — the 21px checkbox, its 1.75px border, the 1.5px strikethrough — are transcribed into `app/globals.css` as `@utility` recipes beside the ten typography roles, because AD-13 forbids an arbitrary-value class and the theme's token counts are pinned exact. Loading, failure and empty stay genuinely absent, marked by comments naming Stories 2.6, 2.7 and 2.8, per the rule Stories 1.7 and 2.3 both kept. Proof follows this repository's established shape — AST scans over the markup surface plus the real Tailwind pipeline compiling the real classes — rather than adding a DOM environment, since every criterion here is either structural or resolves to CSS, and jsdom would compute no Tailwind at all.

## Implementation Notes


**Files.** New: `src/client/components/todo-row.tsx` (`TodoRow`) and `todo-list.tsx` (`TodoList`), each with a node test beside it, plus `src/test-support/tailwind.ts`. Amended: `app/globals.css` (two `@utility` recipes appended), `src/client/components/todo-card.tsx` (the list region's empty `div` became `<TodoList />`), `todo-card.test.ts` (that positional assertion) and `app/page.test.ts` (now imports the extracted compile harness). No new dependency, no new theme token, no change to `vitest.config.mts`.

**The variant marker is `data-completed`, and the shape was chosen for what it keeps working.** AC4 asks for one marker that descendants derive from. A `clsx`-style conditional would satisfy AC4's letter while defeating four separate guards at once: `dynamicClassNames()` in `todo-card.test.ts` permits exactly one computed `className` in the product (`<html>`'s font variable), and every whole-tree scan Story 2.3 built reads `className` *string literals* out of the AST — a row that picked its colours in JavaScript would contribute zero classes to all of them and fail none. With the marker, both class strings stay literal and the only thing that varies is one attribute. Mutation-tested: branching the label's class string fails four tests across two files, including Story 2.3's computed-className wall.

**Tailwind's bare `data-` variants were verified before being relied on, not after.** `data-completed:bg-row-complete` compiles to `.data-completed\:bg-row-complete[data-completed]` and `group-data-completed:*` to `:is(:where(.group)[data-completed] *)`. The arbitrary-value spellings (`data-[completed]:`) would have been banned by AD-13's scan in `app/page.test.ts`, so the bare form was not a style preference — it was the only spelling available, and it had to be confirmed to exist. `in-data-completed:` was also tried and rejected: it compiles to an *unqualified* rule, which would have applied the completed styling to every row.

**Three values in DESIGN.md have no token behind them, and neither `@theme` nor an arbitrary value could hold them.** The checkbox's 21px square and 1.75px border and the Completed row's 1.5px strikethrough live inside `components.*` rather than in DESIGN.md's `colors`/`rounded`/`spacing` blocks. AD-13 forbids an arbitrary-value class, and `app/globals.test.ts` pins the theme to exactly 21 colours, 4 radii and 14 spacing tokens — a fifteenth spacing token fails that test whether or not DESIGN.md grew one. So they are `@utility checkbox-box` and `@utility strikethrough-completed`, beside the ten typography roles, which are already precedent for "a recipe is several properties, not one theme key". `extractTypographyRoles()` matches `@utility text-*`, so neither new recipe disturbs that count.

**`app/globals.css` must not be run through Prettier, which I found by doing it.** Prettier lowercases every hex value in the theme, and both `app/globals.test.ts` (which compares each colour against DESIGN.md's own casing) and `app/page.test.ts` (`--color-ground: #E7EAF6`) pin them uppercase. The file was already not Prettier-clean at HEAD, and there is no Prettier config or dependency in this project at all, so the gates are `lint`, `typecheck`, `test` and the build. The formatting was reverted and the recipes appended by hand. Recorded in `deferred-work.md`, because earlier specs claim "Prettier clean on every file touched" and that claim cannot be true of this file.

**`wrap-anywhere`, not `break-words`, and the difference is the whole of AC5.** Only `overflow-wrap: anywhere` also reduces an element's min-content contribution, which is what lets the text cell in this flex row actually narrow; `break-word` breaks the glyphs and leaves the intrinsic minimum wide, so a 500-character unbroken Todo still pushes the row past the card. The usual companion, `min-w-0`, was unavailable: `todo-card.test.ts` bans `min-w-` across the whole tree as something that can outgrow the card, and that ban is right. This closes the `deferred-work.md` entry Story 2.3 left naming this story as its owner — the product had no wrapping guard anywhere because nothing rendered Todo text to put one on.

**The list region became a component, which is the one structural change to a done story.** Story 2.3 left an empty `div` and named 2.4, 2.6, 2.7, 2.8 and 2.9 as its fillers; its test pinned the card's children positionally as `["StickyTopBlock", "div"]`. That is now `["StickyTopBlock", "TodoList"]` — still positional, still two entries. Putting the client boundary here rather than on the card keeps `TodoCard` a Server Component, and `TodoRow` needs no directive of its own because a module imported from a Client Component is already in the client graph. This is also what finally gives `useTodos()` a caller: Story 2.2's hook had none, so the list reached the browser and stopped.

**Loading, failure and empty are one `undefined` today, and that is deliberate but load-bearing.** `data` is `undefined` both in flight and after a failure, so both fall through the same guard and render nothing. Story 2.7 is where they must stop being the same thing — a failure leaves the contents *unknown* rather than known-empty, and must show neither skeletons nor an empty state. The branches are comments naming their owners rather than placeholder markup, per the rule Stories 1.7 and 2.3 both keep.

**Rendering the component turned out to be free, so the proofs are not only scans.** `react-dom/server` runs in the node environment Vitest already uses, and a `.ts` test may import a `.tsx` module — it is the test file's own extension the `include` glob constrains. So no jsdom, no `@testing-library`, no config change, and the one thing no scan can reach is covered: the marker lands on the element for the right status and nowhere else. The strongest assertion in the suite falls out of it — the Completed markup with ` data-completed="true"` removed is byte-identical to the Active markup, which is AR-28 stated as an equality rather than as a convention. Mutation-tested with a cue branched on an *attribute* rather than a class, which every class scan would have missed.

**Verified:** `npm run lint`, `npm run typecheck`, `npx next build` — all clean; the production CSS carries all eleven new rules, including both `[data-completed]`-qualified ones. `npm test` — 405 passing, 21 of them this story's. The 8 failures are `src/server/repository/todos.test.ts` and `client-identity.test.ts` failing with `password authentication failed for user 'neondb_owner'`; confirmed identical on a stashed tree at HEAD, so the `.env` credential has expired and this story neither caused nor touches them. Six mutations were run and each failed the intended test: a JS-branched class string, a dropped strikethrough, a dropped shadow re-tint, a `truncate`, an `onClick` on the row body, and a status-branched `aria-hidden`. One ordering fact is pinned rather than assumed — `hidden` and `group-data-completed:block` are both `display` utilities on the same element, so the test asserts Tailwind emits the variant rule last; if it ever did not, the glyph would vanish in both statuses with every other assertion still green.

**What no test here reaches.** Nothing has laid a row out in a browser: that 500 characters wrap inside 320px, that the row grows rather than clipping, and that the 44px minimum is honoured are asserted as CSS rules, not measured. And Completion Status is on no accessibility tree — the glyph is `aria-hidden`, a strikethrough carries no semantics, so a screen-reader user cannot yet tell an Active row from a Completed one. Both are in `deferred-work.md` with their owners.

**What review changed, and the worst of it was in the helper I had just extracted.** `ruleFor()` read a rule as `[^}]*\}` — up to the first closing brace. Tailwind v4 emits the shadow utilities with a nested block inside them, so every `shadow-*` assertion in this repository, including `app/page.test.ts`'s existing `shadow-card` one, was matching a truncated fragment. `toContain("--tw-shadow:")` passed on it, which is exactly the silent pass the module exists to prevent. The body is now brace-balanced, the lookahead also rejects `\` and `/` (so `bg-card` cannot match `.bg-card\/50`), and the shadow assertions were rewritten against what is now visible: the green tint, the `[data-completed]` qualifier, and `box-shadow` actually being applied. Two further scans were rescoped — a tree-wide `h-` ban written from this file would have failed Story 2.6's fixed-geometry skeletons and Story 4.4's one-line tab counts from a file neither story touches — and `todo-list.test.ts` was rewritten to stub the hook and render the component instead of running regexes over its source, which caught four regressions the regexes did not.

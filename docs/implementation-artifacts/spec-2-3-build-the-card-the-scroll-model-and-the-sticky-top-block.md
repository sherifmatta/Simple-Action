## Intent

**Problem:** `app/page.tsx` is still Story 1.7's genuinely empty card — one `<main>` and one `<div>`, asserted by `app/page.test.ts` to contain no text and exactly those two elements. It has no interior structure at all, so the four regions DESIGN.md fixes in order (add input → error banner region → filter tabs → list) have nowhere to go, and the sticky top block that AC6 says Epic 3's input and Epic 4's tabs must be *placed inside* rather than re-implement does not exist. Every remaining Epic 2 story renders into a container that has not been built: 2.6's skeletons and 2.8's empty state need the list region, 2.7's banner needs the slot inside the sticky block. The scroll model is equally unstated — the page body being the product's one scrolling element is true today only because nothing has yet had the chance to add a second, and nothing would notice if a later story did.

**Approach:** Move the card out of `app/page.tsx` into the component home AR-20 names (`src/client/components/`), and give it the two structural children this epic renders into: a sticky top block holding the ordered slots for the input, the banner region and the tabs, and the list region beneath it. Keep Story 1.7's rule that a container with no occupant yet stays genuinely empty — ordered comments mark the slots, no placeholder markup a later story has to remember to delete. Everything visible compiles from Story 1.2's `@theme` tokens, with no new token, no new dependency and no DOM environment: the scroll-model criteria are whole-tree structural claims (exactly one `sticky`, no second scroll container anywhere, no fade or inner shadow cueing "more below", no wordmark or title text) and are proved by source scan and by compiling the real classes through the real Tailwind pipeline, the way `app/page.test.ts` already proves the card recipe.

## Implementation Notes

**Files.** New: `src/client/components/todo-card.tsx` (`TodoCard`) and `src/client/components/sticky-top-block.tsx` (`StickyTopBlock`), each with a node test beside it. Also new: `src/test-support/markup.ts`, the shared reader the three tests scan through. Amended: `app/page.tsx` (the card recipe moved out; the page is now its margin and one child) and `app/page.test.ts` (the element pin, and the two guards described below widened from `app/` to the whole markup surface). Removed: `src/client/components/.gitkeep`, now that real modules occupy the directory — the convention Stories 1.3–1.5 and 1.7 followed. No new dependency, no new token, no change to `app/globals.css` or `vitest.config.mts`.

**Moving the card out of `app/page.tsx` had to take its guards with it.** AR-20 puts card, input, tabs, row and banner components in `src/client/components/`, and from this story the card has interior structure, so it moved. But the AD-13 token scan and the Tailwind compilation that proved the card's classes resolve to real tokens both lived in `app/page.test.ts` and both read `app/page.tsx` — scoped to `app/`, they are exactly the kind of guard a directory move walks out from under, silently and with a green suite. Both now run over the whole markup surface — every `.tsx` under `app/` and `src/client/`, read through `src/test-support/markup.ts` — rather than over any list of files (review widened this from the four-file list this story first shipped; see below). This is the one change to a done story's test that was unavoidable rather than convenient: `app/page.test.ts:86` pinned the page's elements to `["main", "div"]`, which AC5 necessarily breaks.

**Both containers stay genuinely empty, which is Story 1.7's rule and not a shortcut.** The sticky block renders one `div` and three comments marking the ordered slots; the list region is an element with a comment naming the three stories that fill it. 1.7's reasoning applies unchanged — a placeholder is something a later story has to remember to delete — and it is what makes AC5 structural now rather than a convention 2.4, 2.6, 2.7 and 2.8 each have to re-observe. `sticky-top-block.test.ts` pins the slot order by parsing the comments, because until an occupant exists the order *is* the file's whole content, and a story inserting its markup in the wrong place would otherwise be caught only once all three had landed.

**AC2, AC3, AC4 and AC6 are absences, so they are scans — over class names from the AST, not over file text.** `todo-card.test.ts` walks every `.tsx` under `app/` and `src/client/` plus `app/globals.css`, and asserts: no `overflow-*-auto|scroll` anywhere; no `overflow-*-hidden` anywhere but `<body>`; no gradient, mask, fade stop, backdrop, inner shadow or scrollbar utility; no width that can outgrow the card; and `sticky`/`fixed` declared in exactly one file — each matched against the class's base utility, with variants and the important marker stripped. Reading `className` string literals out of the TypeScript AST rather than grepping the source is what makes this work at all — every one of these files discusses `sticky`, `overflow`, fades and scrollbars *in its comments*, and the existing tree-walk scans in this repository have to strip comments first to survive that. A `className` literal is also the only thing that actually reaches the browser. Both walls were mutation-tested rather than merely run: adding `overflow-y-auto` to the card fails the AC3 scan, and a second `sticky` planted in `providers.tsx` fails the AC6 scan; the tree was restored after each. A planted-fixture case pins that all five patterns still match something, so a regex that stopped matching cannot pass as an absence.

**`overflow-x-hidden` on `<body>` is an allow-list of one, and the reason is the reason AC3 and AC6 do not collide.** Story 1.7 put it there for DESIGN.md:356, and it looks like a second scroll container sitting directly above the card. It is not: with `<html>` left at `visible`, the used overflow propagates from the body box to the viewport and the body itself computes back to `visible` (CSS Overflow 3 §3.3) — which is also what leaves `position: sticky` working inside the card. The same declaration on any element *below* the body would clip the sticky block instead, so the scan bans the whole family and exempts that one occurrence by exact file and class rather than banning only the `auto`/`scroll` spellings.

**`top-0` and `z-10`, both chosen rather than defaulted.** No numeric offset is given in DESIGN.md or EXPERIENCE.md — "at the top of the viewport" is transcribed literally, and the related live measurement (`scroll-padding-top` sized to this block so a focused control never lands under it) is UX-DR21 and Story 6.1's, which is why nothing here hard-codes a height for it to read. `z-10` is not needed against today's siblings, since a sticky element is positioned and paints above the non-positioned rows in its stacking context anyway; it is for Story 4.5's departure animation and Story 5.6's swipe, where a transformed row makes its own stacking context and would otherwise paint in source order — after this block.

**No DOM environment, and none was needed.** Every criterion here is structural or compiles to CSS, so the proofs are source parsing plus the real `@tailwindcss/postcss` pipeline over the real `app/globals.css`, matching Stories 1.7 and 2.2. What that cannot prove is that `position: sticky` actually holds in a browser under the body's propagated `overflow-x-hidden` — the reasoning above is from the specification, not from an observation. That belongs to Epic 6's route-driven coverage (6.2, 6.5) and to 6.1, which measures this block live; recorded in `deferred-work.md` rather than left implicit.

**What review changed, and it was the scans.** Three of the patches below are the same bug in three costumes: a wall that reads class names can be walked past by writing the class differently. `md:overflow-y-auto` is a scroll container on a tablet and defeated every anchored pattern; `!fixed` defeated them too; and a `className={cn(…)}` defeats all of them *silently*, contributing zero classes and no failure — the shape Story 2.4's row variant marker would most likely arrive in. So `baseUtility()` now strips variants and the important marker before matching, and `dynamicClassNames()` asserts that the only non-literal `className` in the product is `<html>`'s font variable, which carries no utility class. Both were mutation-tested. The patterns also gained the near neighbours they were missing (`w-dvw`/`w-fit`, the `from-`/`via-`/`to-` colour stops that make a fade, `backdrop-*`), and the planted fixture now uses Tailwind 4's `bg-linear-to-t` — the spelling this repository would actually produce — alongside the 3.x one an author copying an older snippet would reach for.

**The guard I widened for this story was still hand-written, which is the same failure one file later.** The AD-13 scan and the token compilation went from reading `app/` to reading a list of four files; a fifth component — 2.4's row, 2.7's banner — would have walked out from under both exactly as the card would have. Both now run over the markup surface, and a probe component carrying a hex literal fails the scan from a file no test names. The card recipe is also pinned as an exact set now: dropping `shadow-card` previously left every positive assertion green.

**`src/test-support/markup.ts` is the home `deferred-work.md` already named.** Three copies of the AST helpers had accumulated across this story's own files. Rather than add a fourth, the markup half of the recorded tree-walk debt is extracted here — `.tsx` under `app/` and `src/client/` — and the six copies of the *generic* source walk stay deferred, for the reason the original entry gives: they scan `.ts` too, they belong to done stories, and two of them pin the exact contents of directories a shared module would join. The entry is re-deferred with the count and the new, smaller shape of the job.

**Four entries went to `deferred-work.md`**, three of them findings this story surfaced and cannot close: that no browser has yet observed `position: sticky` holding under the body's propagated `overflow-x-hidden`; that the block spans only the card's content box, so a row's shadow will bleed into the 18px gutter beside it and an occupant will sit flush against the viewport edge once pinned; and that AC2 is closed by hiding horizontal overflow rather than preventing it, with no wrapping guard for the 500-character unbroken Todo the epic names. None is observable at this baseline — the block has zero height until 2.7, no row exists until 2.4 — and each names its owner.

**Verified:** `npm run lint`, `npm run typecheck`, Prettier clean on every file touched. `npm test` — 377 passing. The 8 failures are `src/server/repository/todos.test.ts` and `client-identity.test.ts`, which query the live Neon branch and fail with `password authentication failed for user 'neondb_owner'`; they fail identically on a stashed tree at HEAD, so the credential in `.env` has expired and this story neither caused nor touches them. `npx next build` succeeds, and the prerendered `index.html` carries the card, the sticky block and the list region in order, with `.sticky{position:sticky}` and `.top-0{top:0}` in the emitted CSS.

## Intent

**Problem:** `app/layout.tsx` mounts nothing but Poppins and `app/page.tsx` renders the string `Simple Action`. There is no query client, no live region, no error slot — so the first feature story to need any of the three would invent its own, which is exactly the per-feature duplication AD-8, AD-9 and AD-12 exist to prevent. `@tanstack/react-query` is not even installed.

**Approach:** Mount the three shell singletons once at the root — a `QueryClientProvider` whose only query key is `['todos']`, exactly one polite and one assertive live region reached through a single `announce(message, urgency)` function, and one error slot holding `{ kind, retry } | null` whose `kind` comes from the shared contract — then render the DESIGN.md `card` recipe as an empty card on the ground at `{spacing.card-max-width}`, built only from the tokens Story 1.2 transcribed.

</frozen-after-approval>

## Implementation Notes

**The one dependency.** `@tanstack/react-query@5.103.2` — the newest release in the architecture's pinned `5.103.x` range, installed with `--save-exact` to match how `next`, `react` and `drizzle-orm` are already pinned in `package.json`. It brings one transitive package (`@tanstack/query-core`). Nothing else was installed; in particular no DOM environment, which is why every test here is a node test (see below).

**`app/layout.tsx` stays a Server Component.** React context is unavailable in Server Components (Next.js `Server and Client Components` guide, §Context providers), and the root layout must own `<html>` and `<body>` (Next.js `layout.js` reference). Marking the layout `"use client"` would have solved the first at the cost of pulling the whole root layout — and `next/font`'s work — into the client bundle. Instead `src/client/providers.tsx` is the single `"use client"` entry point and the layout mounts `<AppProviders>{children}</AppProviders>`. `children` is passed as a prop, so pages below the boundary are still free to be Server Components.

**The `QueryClient` is built in a `useState` initialiser, not at module scope.** A module-scope client is constructed once per *server process*, so under SSR every visitor would share one cache — and this cache holds one person's Todo List, scoped to their Client Identity (AD-7). The honest scope is therefore one client **per mount of the shell**, not per browser session: TanStack's App Router guidance for surviving a remount is a `getQueryClient()` returning a server-fresh client and a browser singleton, which is not used because nothing remounts this boundary today (one child, no error boundary above it). `defaultOptions` is left unset, which means `staleTime: 0` — a real default chosen by omission, for Epic 2's hooks to tune against endpoints that exist.

**React 19's context-as-provider spelling.** `<AnnounceContext value={…}>` rather than `<AnnounceContext.Provider value={…}>`. `@types/react` 19 declares `interface Context<T> extends Provider<T>`, and `.Provider` is the form React 19 deprecates.

**Four files, split pure-from-React, because there is no DOM to test in.** `vitest.config.mts:30` runs `environment: "node"` and its comment records that a `.test.tsx` is deliberately absent — "a component test would fail on a missing document rather than be skipped". So each of the two feedback modules is a pure `.ts` holding the decision plus a `.tsx` holding the React wiring:

- `announcement.ts` / `announcer.tsx`
- `error-slot-state.ts` / `error-slot.tsx`

That is what lets AC4's real claim — a newer error replaces an older one **without retrying the replaced operation** — be asserted against the actual transition function with `vi.fn()` closures, rather than inferred from reading the provider. The `.tsx` halves are checked by parsing their source, the way `app/layout.test.ts` checks the font swap.

**Retrying is deliberately not a reducer action.** Invoking a caller-supplied closure is a side effect, and React double-invokes reducers under Strict Mode in development — a `retry` case in `errorSlotReducer` would re-attempt the failed operation twice per click, against a row that may no longer exist. `error-slot.tsx` calls the closure outside the reducer, and — after review — dispatches `clear` **first**, then invokes it. That order is load-bearing both ways: a closure that throws cannot strand the banner on screen, and a closure that synchronously raises a new error (a retry that fails again, the ordinary case) has that error survive rather than be wiped by a `clear` queued behind it. `error-slot.test.ts` asserts the reducer module contains no `.retry(` call at all, and asserts the dispatch precedes the call by index rather than by proximity.

**`announce()` alternates a trailing no-break space.** A screen reader announces a live region when its text content *changes*; announcing "Todo added" for two Todos in a row would leave the DOM identical and be silently dropped — a real EXPERIENCE.md case. `liveRegionText` appends U+00A0 on even nonces, which changes the text content while changing nothing spoken (U+00A0 has no pronunciation and is not a word separator). The parity is chosen so the *first* announcement renders untouched and only a repeat pays the space; this was caught by the test, not by reading.

**Both live regions are in the DOM from first paint.** A live region inserted in the same commit as its text is not announced by most screen readers — the region has to already exist for the change to be a change. Verified against the real prerendered output (`.next/server/app/index.html` after `npm run build`), which contains exactly `<div aria-live="polite" …></div><div aria-live="assertive" …></div>`, both empty.

**The two guards that carry the most weight were mutation-tested, not just run.** A green suite proves nothing about what it would reject, so each was broken deliberately and the tree restored:

- Deleting `aria-live="assertive"` from the announcer → `announcer.test.ts` fails 2 of 16.
- Making `errorSlotReducer`'s `raise` case call `slot?.retry()` before replacing — the exact regression AC4 forbids → `error-slot.test.ts` fails 4 of 11.

**AC3 got a lint rule, not just a test.** `eslint.config.mjs` gains `noAriaLive` — `no-restricted-syntax` selectors covering the JSX attribute, the literal-property spelling, `setAttribute("aria-live", …)`, and the three *implicit* live regions `role="alert" | "status" | "log"` (each carries an implied `aria-live` in ARIA; the error-banner mockup uses exactly this, so the banner story would otherwise have walked straight past the wall) — restated in every one of the nine boundary blocks, per that file's documented FULL RESTATEMENT invariant, plus a tenth block *last* in the array exempting `src/client/feedback/announcer.tsx` by exact path. `eslint.config.test.ts` gains eleven violating fixtures (a component, an `app/` page, a *sibling* of the exempt file, a query hook, a props object, a root-level module, the three roles, an imperative `setAttribute`) and two allowing fixtures — the announcer itself, and `role="dialog"`, so the rule stays a wall around announcements rather than around ARIA. The exemption is proved file-scoped rather than directory-scoped. `src/client/feedback/announcer.test.ts` then scans the tree independently: comments are stripped first (`app/layout.tsx` and `announcement.ts` both discuss `aria-live` in prose, and `eslint.config.mjs` *is* the rule), and what remains must look like a declaration rather than a mention. Negative fixtures prove the scan rejects every *explicit* spelling, and the test now says plainly that the implicit roles are the lint rule's job, not the scan's — the earlier wording overstated it.

**AC5 needed no new design token and no change to `app/globals.css`.** The `components.card` recipe (DESIGN.md:103-109, 398-400) compiles entirely out of Story 1.2's `@theme` block: `bg-card`, `rounded-lg`, `shadow-card`, `py-6`, `px-gutter`, and — the one that was not obvious — `max-w-card-max-width`. Tailwind 4.3.3's `max-w-*` utility resolves a named key from the `--spacing-*` namespace, not only from `--container-*`, so `--spacing-card-max-width: 640px` produces `.max-w-card-max-width{max-width:var(--spacing-card-max-width)}` with no alias token and no arbitrary value. This was verified by compiling, not assumed; `app/page.test.ts` keeps it verified by driving the real `@tailwindcss/postcss` plugin over the real `app/globals.css`, the way `app/globals.test.ts` proved the `rounded-full` token. The ground sits on `<body>` with `min-h-dvh` — not `min-h-screen`, whose `100vh` is mobile Safari's *large* viewport and would make the page scroll by the URL-bar delta with no content under it — alongside `overflow-x-hidden`, which transcribes DESIGN.md:356's "No horizontal scrolling on the page body, **ever**"; `p-margin-phone` on the wrapper is what leaves ground visible on all sides below 640px (DESIGN.md:352).

**A deferred item from Story 1.2 is closed here.** `deferred-work.md` records that `<body>` was never painted with `--color-ground` / `--color-text-primary`, so the application rendered on Tailwind preflight's white, and names the shell story as the right owner. `<body className="min-h-dvh overflow-x-hidden bg-ground text-text-primary">` closes it; `app/page.test.ts` asserts every class and that each compiles to its token.

**The card is genuinely empty.** No placeholder heading, no wordmark — DESIGN.md §Layout is explicit that nothing sits above the add input, so a placeholder would be something a later story has to remember to delete. `app/page.test.ts` asserts the page contains zero JSX text nodes and exactly two elements.

**Two stale `.gitkeep` files removed.** `src/client/feedback/.gitkeep` and `src/client/todos/.gitkeep`, now that real modules occupy both directories — the same convention Stories 1.3–1.5 followed.

**Not done, deliberately.** No error banner (Epic 2's component; this story mounts the slot it will read), no query hooks, no announcement copy, and no `defaultOptions` on the query client. `TODOS_QUERY_KEY` is exported and not yet consumed: declaring the one key AD-8 permits is the deliverable, and `src/client/providers.test.ts` scans the tree so that any future file naming a query key must import it.

**Added during review triage.** Both providers now refuse a second mount (each reads its own context and throws if one is already above it), which makes "exactly one" structural rather than conventional — a lint rule cannot see a nested provider. And `announcer.test.ts` now renders `AnnouncerProvider` and the whole `AppProviders` shell through `react-dom/server`'s `renderToStaticMarkup`, asserting against the real HTML that there is one polite and one assertive region, both empty, both `sr-only`, and two rather than four. That closes AC2's literal "when the DOM is inspected" with **no new dependency**: it needs no `document`, and the components are built with `createElement` so the file stays `.test.ts` and `vitest.config.mts` is untouched. What is still unproved is hydration — see `deferred-work.md`.

**Out of scope, observed.** `next build` prints `The "middleware" file convention is deprecated. Please use "proxy" instead.` That is Story 1.6's file, untouched here.

Cancel takes initial focus, not Delete — the destructive-default convention, and consistent with nothing in this product ever being lost by accident. A keyboard user who opens this dialog and presses Enter without reading it keeps their Todo. Reaching Delete is one Tab away and deliberate.

Focus is trapped inside the dialog and the screen behind it is dimmed to rgba(36,36,58,.44). Cancel's outline is border-control #8C8BAC (3.28:1) so the button has a boundary that actually resolves; the soft-glow ring sits outside it. Delete is danger-fill #8E3B22 with a white label.

The Todo is named by showing its own text, so no extra sentence enters the interface. Two buttons, both 44px minimum. No undo toast in v1 — the dialog is the whole safety net.

A keyboard equivalent is required regardless of the gesture. Tabbing into the row reaches the same delete control the pointer hover reveals, with the soft-glow ring on it, and it opens the same dialog as Step C — where Cancel, not Delete, is already focused. No swipe is ever the only way through.

The icon here is danger-text #8E3B22 as a foreground on white. The fill token is reserved for the swipe panel and the destructive button.

The ring drawn here is the white-row variant, 0 0 0 1px #2680EB, 0 0 0 5px rgba(38,128,235,.30) — send invoice is Active. A Todo can be deleted in either Completion Status, so this same control is reachable on a mint row, where the ring steps down to accent-deep #1B65C2 (4.33:1) because #2680EB on mint is 2.97:1 and fails the 3:1 non-text floor.

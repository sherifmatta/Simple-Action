The canonical single screen, rendered 1:1 in a phone frame and a desktop browser frame with identical content. Static mock: nothing here responds to interaction, and each state is labelled. Tokens are Lavender Mist (variation 4) plus the two accessibility tokens added at Finalize.

What this screen fixes

  • No wordmark — the card opens straight into the input. The product name lives in the browser tab title only; there is nothing to read before working.
  • Input pinned top — placeholder what needs doing?, thin rounded plus icon in accent #2680EB, row-radius 14px, border border-control #8C8BAC, its own soft shadow so it reads as a sub-surface of the card.
  • Filter tabs with counts — inset segmented control: recessed track #EDEEF7, raised white selected chip, label #1B65C2. Each tab carries a bare count — All 4 / Active 2 / Completed 2 — one type step down, one weight step down, in text-muted, so the count reads as secondary to the view name rather than as a badge. Counts are derived locally from the loaded list, fire no network request, and show 0 rather than hiding. Each count sits inside the tab's accessible name: aria-label="Active, 2 Todos".
  • Rows — each Todo is its own sub-surface, radius 14px, 9px gutter, 50px minimum height. Newest-first by creation timestamp, and completed rows never reorder.
  • Completed — mint #C3E9D7 + filled checkmark in accent-deep #1B65C2 (4.33:1 on mint) + strikethrough in #5F5F7A, all three at once. The checkmark on an Active row stays #2680EB on white.
  • Desktop ceiling — the card caps at 640px and centres in the lavender field. One column at every breakpoint.
  • Delete on pointer devices — trailing icon revealed on row hover only. Touch uses swipe-to-reveal; both are mirrored by a keyboard path. See key-delete.html.
  • Banned — no synonym for Completed appears anywhere; the filter view name matches the Completion Status value exactly. No wordmark, greeting header, stat tiles, categories, sub-tasks, notification bell, timestamps, FAB or second screen.

- (decision) TODO ID: client generates a UUIDv7 and sends it with the create request. Binds: FR-1, FR-2. Prevents: an optimistic row and an arriving list row being unmatchable, forcing a text-match heuristic that breaks on duplicate Todo text. Consequences: merge-by-id is literally true (EXPERIENCE.md's add-during-load race); create is idempotent, so Retry after an ambiguous timeout cannot duplicate.
- (decision) ORDERING: sort key is id DESC (UUIDv7, time-ordered). created_at is server-set per FR-1 but is display metadata, not the sort key. Decided by the architect, not the user — user did not answer the follow-on; flagged for correction. Prevents: a re-sort when an optimistic row reconciles, and the pin-to-top special case that created_at-as-sort-key would need. Serves EXPERIENCE.md's rule that list order is stable under every interaction.
- (decision) CLIENT IDENTITY: opaque token in an HttpOnly, Secure, SameSite=Lax cookie with long Max-Age, issued server-side on first request. Stored HASHED at rest (user chose hashed over plaintext). Todos foreign-key to client_identity.id, never to the token — the indirection the PRD addendum required so attaching a real account later is a nullable user_id on client_identity and nothing else moves. The token authorizes nothing and must never be treated as authentication.
- (decision) API SHAPE: REST route handlers under app/api/todos. Chosen over Next.js Server Actions. Prevents: one story implementing a mutation as a Server Action and another as fetch() — both idiomatic, together two APIs. Largely inherited from input.md ('the backend will expose a small, well-defined API supporting basic CRUD'). Server Actions also produce no inspectable API and fit TanStack Query poorly.
- (decision) PATCH SETS STATE, NEVER TOGGLES: PATCH /api/todos/:id with {completed: boolean}; no /toggle endpoint. Forced by EXPERIENCE.md's Retry rule — 'setting that Todo to the Completion Status the user asked for, not a fresh toggle of whatever it is now'. Makes the endpoint idempotent so a retried toggle cannot flip twice.
- (constraint) ID COLLISION HANDLING (follows from client-generated ids): server must validate the supplied id is a well-formed UUIDv7, and on primary-key conflict must check the existing row's owner. Same owner = idempotent retry, return the existing row. Different owner = 409, never disclose the row. Without this the idempotency win becomes a cross-tenant leak.
- (decision) PARADIGM: layered, with exactly one crossing. UI -> TanStack Query hooks -> fetch -> route handler -> repository -> Drizzle -> Postgres. The HTTP contract is the only crossing between client and server layers; a shared contract module is the only code both sides import.
- (decision) REPOSITORY SEAM: only src/server/repository/* imports the Drizzle client, and every repository function takes ownerId as its first argument. This is the rule that buys back the wall topology A gave up — the single point a future auth check clamps onto, which is what makes the PRD extensibility NFR structural rather than aspirational.
- (decision) SHARED CONTRACT MODULE: src/shared/contract/* defines the Todo wire shape, the error envelope and the validation constants; route handlers and client hooks both import it. Neither side declares its own Todo type. Highest-value rule in the spine — it is what stops server response and client expectation drifting apart story by story.

- (decision) HOLE 1 CLOSED — amended AD-8. Whole-list snapshot rollback is forbidden; a failing mutation reverses only the entity it changed. Found by: two compliant mutations (create and toggle) running concurrently, where create's onError restores a snapshot taken before the toggle and silently undoes it. - (decision) HOLE 2 CLOSED — new AD-16. A create must NOT cancel the in-flight list query; the list response merges into the cache by id. Found by: the standard TanStack optimistic recipe begins with cancelQueries, which directly contradicts EXPERIENCE.md's add-during-load race (skeletons keep pulsing, the list still arrives and merges). Cancel it and the list never lands; let it land unmerged and it overwrites the optimistic row and the Todo disappears. Toggle and delete may still cancel — they act on rows the server already knows.
- (decision) HOLE 3 CLOSED — new AD-17. Client Identity is issued by Next.js middleware on the DOCUMENT request; route handlers never mint one and return 401 without a valid identity. Found by: EXPERIENCE.md makes the input live before the list arrives, so on a first-ever visit a GET and a POST can both be in flight with no cookie — each mints its own identity and the new Todo lands in a different Todo List from the one being read.
